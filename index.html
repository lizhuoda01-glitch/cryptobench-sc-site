CryptoBench-SC

Evaluating Cryptanalysis Agents on Symmetric-Cipher Research Workflows
SymmFlow-Bench Team
Symmetric Cryptanalysis Agent Evaluation

CryptoBench-SC is a workflow-oriented benchmark for evaluating whether AI agents can produce verifiable cryptanalysis artifacts across understanding, recovery, planning, implementation, validation, and repair tasks.

Leaderboard Tasks Methodology Dataset

Evaluation Target

CryptoBench-SC focuses on externally verifiable research artifacts rather than hidden reasoning traces. Agents are evaluated by what they can submit, execute, validate, and repair.

The benchmark decomposes cryptanalysis capability into observable workflow nodes and scores them with deterministic validators, executable oracles, and fidelity constraints.

IR
Primitive / Analysis IR
描述分析对象、攻击目标、轮数、场景和 claim boundary。
Plan
Strategy Artifact
记录后端选择、复杂度意识、验证方案和禁止 shortcut。
Run
Executable Artifact
包含 OCP/CLAASP/MILP/SAT/CP 工件、日志和 solver status。
Fix
Diagnosis & Repair
说明失败根因、修复动作，并重新验证语义保持。
Problem Scope

密码学问题范围

以分组密码差分与线性分析为核心，并覆盖若干扩展方向，用于检验题型框架的泛化能力。

Core
Differential Cryptanalysis
差分特征搜索、权重重计算、DDT 检查、P-layer replay 和 reduced-round claim boundary。
Core
Linear Cryptanalysis
线性近似、相关/偏差估计、线性层一致性和 solver 证书检查。
Extension
Impossible Differential
不可能路径、矛盾传播条件和可验证的区分器边界。
Extension
Integral / Division Property
积分性质、division property 传播和选择明文假设。
Extension
Boomerang / Related-key
boomerang 结构、相关密钥模型和攻击场景保真约束。
Extension
Key-recovery Extension
子密钥猜测范围、候选集合、复杂度估计和是否优于穷举。
Task Types

五类启用任务

五类任务覆盖从结构理解、攻击还原、方案规划到实现验证与失败修复的完整实验闭环。

T1
Primitive 理解与结构化
Primitive Understanding
从规范或源材料恢复 Primitive-IR。
T2
攻击描述还原
Attack Description Recovery
恢复 Analysis-IR、攻击场景和 claim boundary。
T3
分析方案规划
Analysis Planning
在目标和资源约束下选择策略和验证路线。
T4
攻击实现与验证
Realization & Verification
生成并运行后端工件，提交日志和验证报告。
T5
失败诊断与修复
Diagnosis & Repair
根据失败脚本与日志定位根因，修复且不改语义。
Task Package

从题目到可验证对象

每道题都被组织为任务包。构建期完成标签冻结与验证器校准，评测期只做自动评分。

Visible Input题面、源材料、工具预算和输出格式。
Frozen Labels唯一答案字段、可接受集合、必需元素和禁止元素。
Validator Map每个评分字段都能追溯到对应验证器。
Audit Record专家审查、pilot 校准和版本冻结记录。

Analysis Framework

核心分析视角

从任务能力、过程质量、工具收益、保真风险、可靠性和人类基线六个维度观察模型表现。

GPT-5.5 Agent41.8
Claude Opus 4.7 Agent40.9
Gemini 3.1 Pro Agent33.1
DeepSeek-V4 Agent24.6
A1
题型能力分解
比较 T1-T5 的得分差异，定位理解、规划、构造与修复的能力边界。
A2
过程评分贡献
分析 final-only 与分层评分的差异，识别偶然正确但证据链不足的提交。
A3
工具配置影响
比较 model-only、tool-assisted 与 full-agent 在 T4/T5 上的收益。
A4
保真度惩罚
统计降轮、改攻击模型、误读 solver status 和 overclaim 等问题。
A5
可靠性 pass^4
每个模型-任务运行四次，分析稳定成功率而非单次最佳表现。
A6
人类基线差距
对照研究人员子集表现，判断任务是否位于合理研究构念范围内。
Methodology

基准构建流程

从源材料到任务包、验证器和排行榜，形成可复现的评测闭环。

01
源材料收集
规范、安全分析报告、可执行工件、失败日志和中间证据。
02
候选任务抽取
记录来源、认知动作、题型、内容标签、预期产物和保真风险。
03
任务规范化
重写 prompt，确定产物 schema，冻结 hidden labels 与 acceptable sets。
04
验证器构造
Schema、label/set matcher、executable oracle、coverage 和 evidence checker。
05
专家审核校准
至少两名专家审核标签、难度、保真边界，并用正负例校准验证器。
06
版本发布评分
Public Dev 调试，Private Active 排榜，按 S_task、pass^4 和 S_leader 聚合。
